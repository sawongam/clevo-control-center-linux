# Flexikey port notes

Status: all pages and dialogs are ported and render against the simulator. Macros are saved but not applied yet.
Driver (kb.dll) is a documented STUB. Recording only works inside the app window.

## Project layout
- `CC/*.axaml` generated by `tools/xaml2axaml.py` from the decompiled XAML (re-run to regenerate; hand-written template
  replacements live in `tools/overrides.py`: ListBox, ScrollViewer, ScrollBar, TextBox). Re-generation command:
  `python3 tools/xaml2axaml.py reference/decompiled/Flexikey/CC/X.xaml CC/X.axaml --events reference/decompiled/Flexikey/CC/X.xaml.cs --app reference/decompiled/Flexikey/CC/App.xaml`
  (App.axaml, UserControl/MainWindow code-behind are hand-maintained, not regenerated.)
- Code-behind: `tools/cs2avalonia.py` produced the first pass, then hand-fixed. Original namespaces/class names kept
  (`CC`, `CC.UControl`, `CC.FlexiKey`, `Test1`).
- Images: `image/**` (lower-case paths; `Img.Load` and the XAML lower-case everything; `ic_fn+backspace.png` is a copy of `ic_fn-backspace.png`).
- Language strings: `Data/mtlanguage.ini` -> `mtlanguage.ini` in the output dir (UTF-16, read with `Ini`).
- `--page NAME` for screenshots (not in original): main, mouse, mouse-enabled, mouse-key, stats, key, express, express-rec,
  express-done, text, text-done, launch, disable, profile, enabled, extra, extra-full, dialog (see `CC/ScreenshotPages.cs`,
  `CC/Page_FlexiKey.Shots.cs`). The loading splash window (`loading.axaml`) is shown at start-up in normal runs only; not screenshotted.

## Data / file formats (same as original)
- Profiles: `CcPaths.Map("C:\ComboKey")/profile.xml` (-> `~/.config/ripple-cc/ComboKey/profile.xml`), written/read by the
  unchanged `XmlRW` (root/Profile_N/Set_N/Index_N attributes; KeyCode = set-1 scan code, +0xE000 for extended keys).
- Export/import use the same XML via OpenFileDialog/SaveFileDialog shims (`CC/Compat.cs`, Avalonia StorageProvider).
- Registry values go through `Reg` (window_FullScreen, window_Color, language, FA keys, WMI_* ...).
- App settings page 1 offset 8 = keyboard Flexikey status, offset 9 = mouse status, offset 2 = UI language (via InsydeDCHU Read/WriteAppSettings).
  Start-up writes app version bytes (page 0 offsets 28..31 = 1,7,0,0).

## Deviations / stubs
- `CC.FlexiKey/Set2Driver.cs`: kb.dll replaced by a stub (see below).
- `CC/KeyHook.cs` (`Test1.Class1`, `KeyboardEventArgs`): gamefeetlib/Windowshook low-level hook replaced by key events of the app window
  (MainWindow tunnel KeyDown/KeyUp, only while recording). `PhysicalKey` -> set-1 scan code table (`ScanMap`); extended keys +0xE000;
  Pause/RShift/NumLock special cases copied from the original. Original hook is global (WH_KEYBOARD_LL); Monopolize was never used.
- `CC/Clevo_MSG.cs`: WM_COPYDATA to "HkeyTray" -> logged to `ConfigDir/flexikey-hktray.log`.
- Event-log IPC (`clevofnkey^205` = status changed, `^102` = language changed): not delivered; handler kept as `outlog_EntryWritten_Linux(string)`.
- Start-up check `(GetDCHU_Data(16) & 2) == 0 -> "not suitable for this model" + exit` is NOT enforced (cannot be verified; mock returns 0).
- Single-instance check, FASer21.exe (FlexiAccess server) start/kill, `shutdown.exe -f -r -t 0`, hp.dll `Set_effect`, GetProductdll `GetProductID_PCI` (returns 0),
  `Icon.ExtractAssociatedIcon` (launch-app icon stays empty), WMI board probes (`GetClevoType`): stubs/no-ops.
- Window: WPF used `Maximized` (+ registry window_FullScreen default 1). Avalonia: same, but headless screenshots stay 1920x1080.
- Radio-button groups: Avalonia raises `Checked` before un-checking siblings; the three tab radios un-check the others first.
- WPF raised `Checked` for initially-checked radios while loading XAML; the page ctor calls those three handlers explicitly.
- Default TextBox restyled to the WPF Aero2 look (`App.axaml` ClassicTextBox).
- Not verified against the real app (no Windows reference): exact pixel positions; hover/pressed states of every themed control; ScrollBar look inside the profile list.

## Driver stub: what the original passes to kb.dll (implement with uinput/evdev in a later phase)
All calls are `LoadLibrary("kb.dll")` + `GetProcAddress(name)` + cdecl/stdcall call. The stub logs one line per call to
`ConfigDir/flexikey-driver.log` and in `Set2Driver.Calls`. Struct layouts (all int32, little endian):
- `ClevoKB { int VK_Key; int DownDelay; int UpDelay; }` (misnamed: VK_Key is a *set-1 scan code*, +0xE000 when extended, see below)
- `ClevoKeyEx { int key; int status; int DelayTime; }` status 1 = make(down) 0 = break(up) (NOTE: inverse of the XML KeyMakeBreak naming; see SetupMacroKeyEx)
- `KeyboardFilterLog { short KeyCode; short Reserved; short MakeCount; short BreakCount; }`
Functions:
| call | args | when |
|---|---|---|
| `ClearFilterMacro()` / `ClearFilterMacro_Mouse()` | - | start of every `Set_Filiter_Driver` (profile save/apply) and when profile.xml is created first time |
| `EnableFilter()` / `DisableFilter()` | - | keyboard Flexikey on/off (profile IsKbEnable) |
| `EnableFilter_Mouse()` / `DisableFilter_Mouse()` | - | mouse on/off (IsMouseEnable). If neither is enabled both Disable* are called and nothing else |
| `CreateMacroKeyEx(ClevoKB Hotkey[2], ClevoKeyEx Macro[255])` | Hotkey[0].VK_Key = key scan code; Macro from SetupMacroKeyEx | keypress action (keyboard). Called 3 times: Hotkey = {code}, {57463, code}, {57464, code} (57463 = 0xE077, 57464 = 0xE078: the Fn-prefixed variants of the key) |
| `CreateMacroKey_MouseEx(int btn, ClevoKeyEx Macro[255])` | btn = 1 left, 4 right, 0x10 middle, 0x40 backward, 0x100 forward | keypress action on a mouse button |
| `CreateMacroKey(ClevoKB Hotkey[2], ClevoKB Macro[16])` | disable: Macro[0] all zero (VK 0) | key disable action (3 calls as above); `CreateMacroKey_Mouse(btn, Macro[16])` for mouse buttons |
| `CreateStringKey(ClevoKB Hotkey[2], ClevoKB Start[6], byte* utf16le_text, ClevoKB End[6])` | text = Encoding.Unicode bytes of TextContent; Start = "start key" combo, End = "send key" combo | express-text action (3 hotkey variants); mouse: `CreateStringKey_Mouse(btn, Start[6], text, End[6])` |
| `CreateFilterSysEvent(ClevoKB Hotkey[2], int EventID)` | EventID = 256 + running index of launch actions in the profile (`AppEventId`, assigned in SaveCurrentProfile) | launch-app action (3 variants); mouse: `CreateFilterSysEvent_Mouse(btn, EventID)`. The driver raised a system event; a Windows service started `AppPath` from profile.xml for that id |
| `StartFilterLog()` / `StopFilterLog()` / `CountFilterLog()` / `GetFilterLog(int i, KeyboardFilterLog*)` | - | statistics page; level from BreakCount: <=4:1, <=8:2, <=12:3, <=16:4, >16:5 |
Macro encoding (`SetupMacroKeyEx(List<MacrokeyContent>, bool useDelays)`): macro[0] = {key=m[0].KeyCode, status=1, delay=m[1].KeyDelay};
for i in 1..n-2 (skip KeyCode 0): {key, status = (KeyMake?1:0), delay = useDelays ? m[i+1].KeyDelay : 0}; final entry {key = m[last].KeyCode, status 0, delay 0}
(max 32 entries; up to 16 make events - enforced by the UI in `CheckExpressLimit`). Delays are milliseconds (0..60000).
Order of calls after a save: Clear*, Enable/Disable Filter, 50 ms sleep, then per KeyInfo in profile order: keypress -> SetMacroKey, launch -> SetLaunchApp,
text -> SetTextMacro, disable -> SetKeyDisable.
Not used at runtime by the UI (kept as methods): `SetKbMacroKey`, `SetMouseMacroKey` (old 16-entry variants).

## Hardware commands sent by the UI (RIPPLE_CC_MOCK_LOG)
Only InsydeDCHU app-settings reads/writes: WriteAppSettings(0,28..31) at start, ReadAppSettings(1,8/9) (Flexikey KB/mouse status), WriteAppSettings(1,8/9) when
the Enable/Disable switches change, ReadAppSettings(1,2) language, ReadAppSettings(0,0,2) product id; `GetDCHU_Data(70/16)`, package 17 reads (skin colour, 3-col numpad flag at byte 14),
`SetDCHU_DataEx(4, buf[0]=12)` (panel size -> 14-inch layout). No performance/fan/LED commands.

## Fix: mouse outline on Keyboard Macro tab
The original binds `grid_mouse`/`image_MouseDisable` visibility to `SL_FlexiKey_Mouse_status.Visibility` (collapsed on the keyboard tab by `UpdateUI_KB_Mouse_Status`). The port had `IsVisible="{Binding Visibility, ...}"`, which binds to a nonexistent property and left the mouse always visible. Now `{Binding IsVisible, ElementName=...}` (all 7 such bindings). Verified by screenshots of main/mouse/stats.
